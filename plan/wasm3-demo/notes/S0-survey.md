- Milestone: planning (before W0)
- Date: 2026-11-15
- Repo commit: 354f87c (gen/wasm-3.0 regenerated by `make -C translate check-3.0`)
- JSCL: jscl-project/jscl@54c88494e9f8f22e4c24c666e84aab7053f18cee (2026-11-14)
- Status: final
- Feeds demo plan: §2 (starting point), §5 risks, W0 and W1

## Summary
The generated 3.0 semantics is 27 books and 486,141 lines. One book,
`5_3-binary_instructions`, is 18 MB. The code uses a small set of operators
(mostly `let`/`let*`, `car`/`cdr`, `equal`, `eq`, `and`, ACL2's `len`), plus
a few ACL2 events that are wrappers. JSCL cannot run it unchanged. Its
numbers are JS doubles only, and the semantics needs bignums (i64, v128,
`2^64` constants) and exact rationals (floats are computed as rationals in
`rt/builtins.lisp`). Memory is a list of `65536 × pages` bytes, built by
recursion, and JSCL's `equal` recurses on `cdr`, so the JS stack is the
second risk.

### JSCL at 54c8849
- `integerp` and `rationalp` are the same test (`%integer-p`). There are no
  ratios and no bignums: numbers are JS doubles, `most-positive-fixnum` is
  `Number.MAX_SAFE_INTEGER` (2^53 − 1).
- `integer-length` signals an error above 2^30. `src/format.lisp` says
  BigInt support was not possible "for now".
- `equal` recurses on `car` and on `cdr`. A 65,536-element byte list goes
  65,536 frames deep.
- Ahead-of-time build: `jscl-xc::compile-application` (host Lisp: SBCL)
  writes one JS file from a list of Lisp files. `declare` forms are parsed
  by `parse-body`; W0 checks whether `xargs` is ignored or rejected.

### Stack depth
- `$ALLOCMEM` builds `:BYTES` with `$ALLOCMEM/ITER2 0 (* I (* 64 ($KI))))`,
  one element per byte, by recursion (W0 checks whether it is a tail call).
- A recursive `%size`/`acl2-count`, `equal`, `len` or `append` over the
  store also goes as deep as the longest list.

## Open questions (for W0 and W1)
- How large is the JS, and how long do the compile and the load take?
- What is the deepest recursion on a module with one page of memory? Can
  node's `--stack-size` and a browser Worker reach it?
- Number representation: see W1.
