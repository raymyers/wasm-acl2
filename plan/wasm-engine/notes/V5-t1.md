## Summary

- **V5 is complete and T1 certifies.** Two new books,
  `engine/machine/spec-result.lisp` (2.3 s) and
  `engine/machine/opcodes.lisp` (3.0 s), certify under
  `make -C engine check`. The gate has 31 books (29 before), no
  `skip-proofs`, no `defaxiom`, no trust tag.

  ```lisp
  (defthm machine-step-simulates                 ; C2, 927 prover steps
    (implies (and (machine-ok s) (machine-running s))
             (equal (stepn (machine-clock s) (machine-abs s))
                    (list (machine-abs (machine-step s))))))

  (defthm machine-result-is-spec-result          ; T1, 551
    (implies (and (machine-ok s)
                  (machine-result-p (machine-run n s))
                  (natp fuel)
                  (< (machine-clocks n s) fuel))
             (equal (w3t::steps/%fuel fuel (machine-abs s))
                    (list (machine-abs (machine-run n s))))))
  ```

  T1 is the statement of plan2.md §1, word for word. It has no
  hypothesis about an opcode. F1 is met.
- **No opcode is excluded, so the machine did not change** (§4). V5
  item 4 expected a proved set smaller than the supported set and a
  machine that refuses the difference. V2 to V4 proved C2 for a symbolic
  head: the proved set is every head on which `op-step` tries a rule.
  The table `*proved-opcodes*` is computed from the machine's own tables
  (48 opcodes), and two theorems say that `op-step` and `machine-step`
  end `:unsupported` outside it, before any rule is tried. That was
  already how the machine behaved. Test 2 was not run again: no machine
  function changed.
- **Bulk memory is clock 1** (§3). `machine-clock` is 1 for every
  instruction that is not a value and not an administrative term, and C2
  is proved with that clock; `memory.fill`, `memory.copy` and
  `memory.init` are not a special case. `machine-clock` did not change.
- **The slides on the list machine are inside T1** (§5): 12 runs (the
  instantiation, four getters, seven slides), the hypotheses of T1
  checked at run time on each, 7 of 7 slides identical to V8. The viewer
  caption says so; for the fast machine it says that there is no theorem
  yet.
- **P2 is now the user's question** (plan2.md §2: "decide after V5").
  §6 lists what is known about its cost. It blocks nothing: V6 is next.

## Findings

All prover steps are from the certification output
(`data/v5-t1/measure.txt`).

### 1. C2 for every running state (V5 item 1)

`machine-clock` is 0 or 1. Clock 0 is `machine-clock-0-simulates`
(`clock0.lisp`, E6). Clock 1:

- `machine-step-clock-1-cases` (7,473 steps): if the state runs and its
  clock is 1, then one of four holds. Each is a step function together
  with the tests `machine-step` made before it called it:

  | Disjunct | `machine-step s` is | Theorem that uses it |
  |---|---|---|
  | `(consp (ms-ctrl s))` | `(exit-step s)` | `exit-step-simulates` (V4) |
  | head `:throw_ref`, top of the stack of head `:ref.null_addr` | `(op-step s)` | `op-step-simulates-throw_ref-null` (V4) |
  | head `:trap` or `:throw_ref` | `(anyprefix-step s)` | `anyprefix-step-simulates` (V4) |
  | head not administrative, not `:trap`, not `:throw_ref` | `(op-step s)` | `op-step-simulates` (V3) |

  Proved by opening `machine-step` and `machine-clock`; no rule function
  and no step function is opened. The two cases of `machine-step` that
  call `exit-step` (no instruction left; `br`, `return`, `trap`,
  `throw_ref` first) are one disjunct.
- `machine-step-runs-when-clock-1` (5,192): a clock of 1 says that the
  state runs and the step ends `:run`, which is the last hypothesis of
  each of the four theorems.
- `machine-clock-1-simulates` (31,884): the four theorems, by `:use`.
- `machine-step-simulates` (927): the two clocks.

The open question of [V4-exits](V4-exits.md) ("the heads of the last
case have to be shown to be neither administrative nor
`TRAP`/`THROW_REF`") is the fourth disjunct; it follows from
`exit-instr-p` being false there.

### 2. The instance (V5 item 2)

`machine-result-is-spec-result` is
`engine-result-is-spec-result` (`theorem/simulation.lisp`) with
`m-ok`, `m-running`, `m-result-p`, `m-step`, `m-abs`, `m-clock`, `m-run`
and `m-clocks` replaced by the machine's functions. The four constraints:

| Constraint | Theorem | Book |
|---|---|---|
| C1 | `machine-step-preserves-ok` | `machine/ok.lisp` (E6) |
| C2 | `machine-step-simulates` | `machine/spec-result.lisp` |
| C3 | `machine-result-is-terminal` | `machine/terminal-ok.lisp` (E3, E6) |
| C4 | `machine-result-not-running` (51 steps) | `machine/spec-result.lisp` |

- `machine-clocks` is new (`spec-result.lisp`): the definition of
  `m-clocks` for the machine, guard `(natp n)`, verified. It is defined
  there and not in `machine.lisp`, so that no book of `fast/` is
  certified again.
- ACL2 proved the constraints and the two definitional ones (`m-run`,
  `m-clocks`) with no hint: 551 steps for the whole event.
- **Hypotheses of T1**: the four of plan2.md §1 and no other.
  `machine-ok` is the invariant of `ok.lisp`, with the conjunct V3 added.

### 3. Bulk memory (V5 item 3)

E5 expected one machine step for a whole `memory.fill` and a clock that
counts the spec steps. This machine does not do that: it applies the
spec's rule, which rewrites the instruction to smaller ones.

| Opcode | Rules in the machine's table (all read rules) |
|---|---|
| `memory.fill` | `-oob`, `-zero`, `-succ` |
| `memory.copy` | `-oob`, `-zero`, `-le`, `-gt` |
| `memory.init` | `-oob`, `-zero`, `-succ` |

Each firing is one spec step, and `machine-clock` says 1 for these heads
as for any other. That is not checked by a test here: it is what
`machine-step-simulates` proves, since `op-step-simulates` has no
hypothesis about the head. `machine-clock` is unchanged, so test 1 was
not run again.

### 4. The table of proved opcodes (V5 item 4, P3)

`machine/opcodes.lisp`.

- `*proved-opcodes*`, by `make-event` from `*rule-places*`: the heads
  `kw` with a rule at the place `(:op kw)` and an operand count from
  `redex-arity`. 48 opcodes:

  ```
  unreachable nop drop select ifelse br_if br_table br_on_null
  br_on_non_null call_indirect local.tee ref.is_null ref.as_non_null
  ref.eq unop binop testop relop cvtop block loop call throw_ref
  try_table local.get global.get table.get table.fill table.copy
  table.init load memory.size memory.fill memory.copy memory.init
  ref.null ref.func ref.cast call_ref throw local.set global.set
  table.set table.grow elem.drop store memory.grow data.drop
  ```

- `op-step-outside-proved-opcodes` (8,793 steps): for a head outside the
  table, `(op-step s)` is `(ms-with-status :unsupported s)`.
- `machine-step-outside-proved-opcodes` (219,009): the same for
  `machine-step`, when the state runs and the head is not a value, not
  an administrative term and not `br`, `return`, `trap` or `throw_ref`.
  Those four have no rule of their own opcode in `op-step` (but
  `throw_ref` under a null reference, which is in the table): their
  rules are those of a control entry or of the whole block, and C2 holds
  for them (§1).
- Census, printed at certification and checked by the book's last
  event: `PROVED-OPCODES-CENSUS 48 opcodes; D5 missing NIL; instantiation
  missing NIL`. "D5" is `*d5-opcodes*` of `fast/frame.lisp` without `br`
  and `return` (33 opcodes; the list is written again in the book, which
  does not include `fast/`); "instantiation" is `memory.init`,
  `data.drop`, `ref.null` ([V0-ground](V0-ground.md) §1). The book fails
  if the table has another size or loses one of them.

**Where this departs from the plan's words.** The item says "an opcode
outside it stops the machine `:unsupported` before any rule is tried"
and "Test 2 re-run". P3's recommendation was written when C2 was
expected per group (S0 to S3). It was proved for a symbolic head, so:

- the proved set is larger than D5. It has 15 opcodes D5 does not name
  (the table and reference instructions the machine already supported:
  `br_on_null`, `br_on_non_null`, `ref.is_null`, `ref.as_non_null`,
  `ref.eq`, `ref.func`, `ref.null`, `table.fill`, `table.copy`,
  `table.init`, `table.set`, `table.grow`, `elem.drop`, `memory.init`,
  `data.drop`), and `call_ref` of a host function (H): T1 holds for
  every `%hostcall-hook`. P1 concerns the fast machine and the TeX
  driver, not T1;
- the machine already refused every other head in the first test of
  `op-step`, so nothing had to be added to it. The two theorems make
  that a proved statement about the table;
- no machine function changed, so the agreeing commands of test 2 are
  those of [V4-exits](V4-exits.md) §8 by construction.

What P3 asked for holds: the theorem is unconditional and the subset is
a constant in a certified book.

### 6. For P2 (the stuck direction)

P2 was left for after V5, "when the dispatch lemmas exist and the cost
can be measured". What exists, without a new measurement:

- `machine-step` ends `:stuck` in six places: `enter-step` on a term
  that is not `enterable-p`; `exit-step` when no rule of the entry
  fires; `anyprefix-step` when neither rule fires (or the result is not
  a true list, which §1 of [V4-exits](V4-exits.md) shows cannot happen);
  `op-step` with fewer values than the arity; `op-step` when no rule of
  the opcode fires; `br`, `return`, `trap`, `throw_ref` first with an
  empty control stack and not the result shape.
- Lemmas that V10 would start from: `no-step-below-arity` (V2, the
  fourth place for a flat block); `step-of-vals-exit-instr-rest` (V3, a
  block at `br`, `return`, `return_call_ref` does not step); the 210
  shape and 201 length lemmas (V1); `try-rules` over the table is the
  three relations on a redex (V1), so "no rule of the opcode fires" is
  "`STEP_PURE`, `STEP_READ/SPLIT` and `step-own` fail on the redex".
- What is missing for each place is the lift: a block that does not step
  under a control stack whose entries have no exit rule that fires. V3's
  context lemma is for a block that steps.
- The two machine bugs of V3 and V4 were of this kind (the machine and
  the spec disagreed on whether a state steps), and the second was the
  stuck direction exactly. A proof of V10 would have found it.

No cost in prover steps or sessions is claimed here: none was measured.

### 7. What failed first

- **`redex-arity` on an empty state, in `make-event`.** The table is
  computed by calling `(redex-arity (list kw) nil nil)`. For `block`,
  `loop`, `try_table` and `throw` it calls spec functions, which are
  `:logic` without verified guards:

  ```
  ACL2 Error [Evaluation] in ( MAKE-EVENT (CONS ...)):  The guard for
  the function call (NTH ACL2::N ACL2::L), which is
  (AND (INTEGERP ACL2::N) (>= ACL2::N 0) (TRUE-LISTP ACL2::L)), is violated
  by the arguments in the call (NTH NIL NIL).
  ```

  Now the expansion is inside `(with-guard-checking :none ...)`. Only
  "there is a count" is used, not the count. The theorem
  `op-step-outside-proved-opcodes` does not depend on how the constant
  was computed.
- **`machine-step-outside-proved-opcodes` with `exit-instr-p` disabled**
  and `op-step-outside-proved-opcodes` by `:use`. The checkpoint:

  ```
  (IMPLIES (AND (EQUAL (MS-STATUS S) :RUN) (CONSP (MS-IS S))
                (NOT (VALUE-INSTR-P (CAR (MS-IS S))))
                (NOT (EXIT-INSTR-P (CAR (MS-IS S))))
                (NOT (MEMBER-EQUAL :TRAP '(:UNREACHABLE :NOP ...)))
                (EQUAL (ENTRY-KIND (CAR (MS-IS S))) :TRAP)
                (CONSP (MS-VALS S)))
           (EQUAL (ANYPREFIX-STEP S) (MS-WITH-STATUS :UNSUPPORTED S)))
  ```

  The hypotheses contradict each other (`:trap` is an `exit-instr-p`
  head) but the prover could not see it with the definition closed. Not
  a machine state. Now `exit-instr-p` is enabled in that proof and the
  lemma is used as the rewrite rule it is.
- Every other event went through at the first attempt. No failed
  checkpoint was a state the machine can reach.
